Process Flows & State Machines

Juneflow Construction ERP · 7 กระบวนการหลัก + Approval Matrix · อ้างอิงพฤติกรรมจริงจาก prototype (5 ก.ค. 2569)

FLOW-Aจัดซื้อ: BOQ → PR → PO/WO → GR → AP → จ่ายเงิน

เส้นหลักของต้นทุนโครงการ ทุกเอกสารอ้างอิงกันเป็นลูกโซ่ (traceability) และตัดยอดคงเหลือ BOQ
BOQ อนุมัติ (ล็อก)→เลือกรายการ → สร้าง PR→PR รออนุมัติ (ตาม matrix)→อนุมัติ→เปิด PO (วัสดุ) / WO (จ้างเหมา)→GR รับของ (เต็ม/บางส่วน/ตีกลับ)→AP ตั้งหนี้ (3-way match PO+GR+INV)→PV รออนุมัติ→จ่าย / Export to Bank
  • กติกา: BOQ ที่อนุมัติแล้วแก้ไม่ได้ ต้องเปิด Revise v(n+1) แล้วอนุมัติใหม่ · รายการที่เปิด PR แล้วถูก mark ตัดยอดคงเหลือ
  • PR แยกชนิด: Material→PR ปกติ · Subcon/Labor→PR-Subcon (แยกใบอัตโนมัติ) · ราคาเกิน BOQ ต้องแนบเหตุผล
  • GR ตีกลับ: สร้างรายงานของเสียหาย + รูป → เข้า DMS + ศูนย์ตรวจรับ → ผู้ขายส่งใหม่
  • VO (งานเพิ่ม-ลด): อ้างสัญญา/PO เดิม → อนุมัติ → ปรับมูลค่าสัญญา
  • สถานะ PR/PO/PV: draft → pending(ขั้น 1..n) → approved | rejected → closed/paid

FLOW-Bงวดงานผู้รับเหมา + ศูนย์ตรวจรับ (Acceptance & Defect Loop)

รับงานได้ 3 เกณฑ์: % ความคืบหน้า · ระยะทาง (เช่น วางท่อ 100 ม./งวด) · Milestone — และงานตรวจรับทุกชนิด (GR/งวด/บ้านลูกค้า) รวมที่ศูนย์ตรวจรับ
งวดถึงเกณฑ์ (%/ระยะ/milestone)→ผู้รับเหมาส่งมอบ + เอกสาร/รูป (เข้า DMS)→นัดตรวจ (โฟร์แมน mobile)→ผ่าน → อนุมัติจ่ายงวด → AP
↘ตีกลับ + Defect List (รายข้อ+รูปก่อน/หลัง)→ผู้รับเหมาแก้ไข (กำหนดเวลา)→ตรวจซ้ำ→ผ่าน (Defect ปิด, เอกสารอัปเวอร์ชัน)
  • หัก Retention ตามสัญญา (เช่น 5%) ทุกงวด → คืนเมื่อครบประกันผลงาน
  • งานตีกลับแจ้งเตือน: ศูนย์แจ้งเตือน + Mobile โฟร์แมน + Dashboard ผู้บริหาร + Audit Log

FLOW-CPM · บำรุงรักษา (CMMS)

โครงการ→สัญญา PM (MA ตามเงื่อนไข | รายครั้ง n ครั้ง/ปี)→แผน PM (รายครั้ง auto-gen ลงปฏิทิน)→ใบงาน PM→ช่าง check-in GPS→Checklist (รูปก่อน→ผล Normal/ปรับตั้ง/เปลี่ยน-ซ่อม→รูป/วิดีโอหลัง)→ปิดงาน + ลายเซ็นลูกค้า→ใบรับรองผล → LINE ลูกค้า
  • หนึ่งโครงการมีหลายสัญญาได้ · สร้างสัญญา = เลือกโครงการก่อนเสมอ (หรือเพิ่มโครงการใหม่ manual)
  • พบอะไหล่ต้องเปลี่ยน → ใบเสนอราคา → ลูกค้าอนุมัติ/ปฏิเสธผ่าน LINE OA → ทำงานต่อ
  • Checklist templates ตั้งค่าได้ (ต่อชนิดอุปกรณ์) เลือกใส่ตอนสร้างใบงาน · สัญญาใกล้หมดอายุ → แจ้งต่ออายุ
  • สถานะใบงาน: open → inprogress → done | overdue

FLOW-Dงานสำรวจ & จัดหาที่ดิน

จัดหาแปลง→สำรวจ-รังวัด (+Cost Center บันทึกค่าใช้จ่าย)→Feasibility (อสังหาฯ=ยูนิต · โซลาร์=MWp/ROI)→Due Diligence 7 ข้อ (ผ่าน/ติดปัญหา/รอ)→เจรจา→ซื้อ (มัดจำ→นัดโอนกรมที่ดิน) | เช่า (25-30 ปี + escalation + จดทะเบียน>3ปี)→ปิดดีล/โอน → Land Bank

FLOW-Eขาย-CRM → โอน → After-Sales (อสังหาฯ)

Lead/Walk-in→นัดชม→จอง (เงินจอง)→สัญญาจะซื้อจะขาย→ผ่อนดาวน์รายงวด→ยื่นกู้/อนุมัติสินเชื่อ→ตรวจรับบ้าน (Defect loop เดียวกับ FLOW-B)→โอนกรรมสิทธิ์ → รับรู้รายได้→After-sales แจ้งซ่อม (LINE)
  • สถานะยูนิต: ว่าง → จอง → สัญญา → โอนแล้ว · การเงินผูก AR อัตโนมัติ (เงินจอง/ดาวน์/ยอดโอน)

FLOW-Fบัญชี: GL Posting → ปิดงวด + e-Tax

เอกสารต้นทาง (PV/RV/GR/ค่าเสื่อม/ค่าแรง/ปันส่วน)→GL Posting Inbox (ตรวจ+post, gen JV อัตโนมัติ)→งบทดลอง / งบการเงิน / P&L รายโครงการ / กระแสเงินสด→กระทบยอดธนาคาร (นำเข้า statement+จับคู่)→ปิดงวด (ล็อกย้อนหลัง)
  • e-Tax Invoice: ออกใบกำกับ → เข้าคิว e-Tax → ส่งสรรพากร (mock) → สถานะ ส่งแล้ว/ตีกลับ
  • รับรู้รายได้ (Revenue Recognition): % of completion + WIP ต่อโครงการ · ภาษี: ภ.พ.30, ภ.ง.ด.3/53 + 50 ทวิอัตโนมัติจาก PV ที่หัก WHT

FLOW-GSubscription Platform (เจ้าของระบบ ↔ ลูกค้า)

ลูกค้าสมัคร/ทดลองใช้→เลือกแพ็กเกจ S/M/L/Full→ระบบเปิดเมนู+โควต้าตามแพ็กเกจ (sidebar กรองอัตโนมัติ)→ออกบิลรายเดือน/ปี→ค้างชำระ → ทวงถาม → ระงับ→ต่ออายุ/อัปเกรด
  • เจ้าของระบบตั้งแพ็กเกจเอง: ราคา โควต้า (โครงการ/ผู้ใช้/พื้นที่/AI ต่อเดือน) + ติ๊กเลือกเมนูที่ปล่อยรายเมนู จากโครงเมนูจริง
  • กติกาพิเศษ: Dashboard + "แพ็กเกจของฉัน" เห็นเสมอ · Project Type เฉพาะ Full · AI QTO เฉพาะ M ขึ้นไป · เครดิต AI หมด → modal อัปเกรด
  • Admin คุมรายบริษัท: เปลี่ยนแพ็กเกจ/seat, บล็อก user, รีเซ็ตรหัสผ่าน, ระงับการใช้งาน

MATRIXApproval Matrix (ขั้นอนุมัติตามมูลค่า)

เอกสารขั้น 1ขั้น 2ขั้น 3หมายเหตุ
PR ใบขอซื้อหน.จัดซื้อ (ทุกใบ)ผจก.โครงการ > 500,000MD > 2,000,000ราคาเกิน BOQ ต้องแนบเหตุผล
PO / WOหน.จัดซื้อผจก.โครงการ > 1,000,000MD > 5,000,000ผูกงวดงาน+retention ตอนเปิด WO
PV ใบสำคัญจ่ายบัญชีผจก.การเงิน > 500,000MD > 2,000,000ผ่าน 3-way match ก่อน
BOQ / Reviseผู้ประมาณราคา (ส่ง)ผจก.โครงการMD (ทุก revise)เทียบ diff v เดิมก่อนอนุมัติ
VO งานเพิ่ม-ลดผจก.โครงการMD > 500,000—ปรับมูลค่าสัญญาอัตโนมัติ
รับงวดงาน (ตรวจรับ)โฟร์แมน (ตรวจหน้างาน)ผจก.โครงการ (อนุมัติจ่าย)—Defect ทั้งหมดต้องปิดก่อน
ปิดงวดบัญชีสมุห์บัญชีผจก.การเงิน—กระทบยอดธนาคารครบก่อน
